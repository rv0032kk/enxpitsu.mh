## 1. 製品の概要

一人称視点（FPS）で仮想3D空間を探索し、水平器をより水平な場所に置いて、水平度、場所、設置までの時間を競うスマートフォン向けオンライン対戦ゲームである。撃ち合いや参加者同士の接触はない。参加者全員が同じステージ、同じ配置、同じ傾きの条件で同時に探索を開始し、他の参加者が動く様子を見ながら置き場所を判断する緊張感を体験の中心の一つとする。

### 3.1 クラウドビルドの方針

Macを用意しないため、iOSアプリのビルド、署名、App Store Connect への提出はすべてクラウド上の macOS 環境で行う。アプリのビルドには Codemagic を第一候補とする。理由は、個人アカウントに macOS の無料ビルド時間が毎月付与されること、および App Store Connect API キーを使って署名用の証明書とプロビジョニングプロファイルを自動で作成・取得できるため、Mac なしでの署名作業の負担を下げられることである。サーバ側（Cloudflare Workers）のテストとデプロイは、Linux 環境で安価に実行できる GitHub Actions で行う。

## 4. 機能要件

### 4.1 ゲームプレイ（企画書 02・03章）

1. 一人称視点で、移動、見回す、置く、測定結果を見る、持ち上げる、確定するの各操作ができる。
   - 左手の仮想スティックで移動し、右手のスワイプで視点を動かす。置く、持ち上げる、確定するなどはボタンで操作する（ボタン配置は試作で決める）。
2. 水平器は接する面の向きに沿って置かれ、安定した後に測定結果を表示する。
3. 水平は前後と左右の2軸で判定する。一方向だけ水平に見える置き方で高得点にならないようにする。
4. 水平器の底面が十分に支えられていることを、有効な設置の条件とする。位置補助を設ける場合も、面の傾きはそのまま測る。
5. 場所点は置く前に確認でき、正確な水平度は置いて初めて分かる。
6. 記録を確定すると、そのラウンドの記録は変更できない。持ち上げると直前の記録は破棄される。
7. 制限時間に達した時点で、安定して置かれている最後の記録を採用する。持ち歩いている場合や安定していない場合は未設置とする。
8. 採点（仮）：水平度70点、場所20点、速さ10点の合計100点。
   - 水平点：傾き0°で70点とし、直線的に減点する。1°以上は無効とする。
   - 時間点：制限時間（90秒）で10点から0点へ直線的に減点する。基準時刻は、水平器を置いて安定した時刻とする。
   - 傾きが許容範囲を超える場合や不安定な場合は、場所点と時間点も含めて無効とする。
   - 同点の場合は水平度、設置時刻の順で比べ、どちらも同じなら同順位とする。
9. 結果画面では、水平、場所、速さの内訳を表示する。

### 4.2 対戦（企画書 02・04章、打ち合わせ決定事項）

1. 人数4〜8人、1ラウンド90秒、3ラウンド制を仮の値とする。
2. ラウンドごとに一つのステージを選び、全員に同じ配置と傾きを適用する。開始位置、向き、移動能力、水平器の性能は全員同じとする。
3. カウントダウンの終了と同時に、全員が一斉に探索を開始する。
4. 対戦中は、他の参加者の位置と動きを各端末にリアルタイムで表示する（打ち合わせで決定）。
5. 参加者同士は接触しない（すり抜ける）。
6. 一つの設置面に置ける水平器は一つだけとする。他の参加者が置いている設置面には置けない。ほぼ同時に同じ設置面へ置こうとした場合は、サーバが受信した順に判定する。他の参加者が水平器を持ち上げた場合、その設置面には再び置けるようになる。
   - 設置面は、ステージの制作時に設定する単位とする（机の天板、棚の各段など）。各設置面は、場所点と、試合ごとに決まる一つの傾きを持つ。一つの設置面の中では、置く位置によって傾きは変わらない。
   - 床のように広い面は、大きさに応じて一定の規則で複数の設置面に区切る。区切った設置面は、それぞれ異なる傾きを持つ。区切り方の規則は技術設計書で定める。
   - 狙っている設置面の範囲が分かるように表示する。
   - 【企画書 v1.0 からの変更】企画書 04章の「置き場所の占有が探索を妨げない形式」を変更した。
7. 試合中、他の参加者が水平器を置いた位置と置く動作を表示する。測定値は試合中は他の参加者に公開しない。
8. 傾きの設定はステージと試合ごとにわずかに異なる。参加者は、ボールや卵などの不安定な物（アイテム）をランダムに取得し、水平器を置く前に設置面へ置いて傾きを確かめられる。【企画書 v1.0 への追加】
   - アイテムごとに、結果が分かるまでの時間を設ける。
   - アイテムは販売しない（第4.5節3項の、購入で測定条件を変えない方針との整合のため）。
   - アイテムはステージ内に置かれており、参加者が拾って取得する。どのアイテムがどこにあるかは試合ごとに変わる（案）。
   - 各種類のアイテムはステージ内に1個ずつしかなく、先に拾った参加者だけが使える。拾う操作が重なった場合は、サーバが受信した順に判定する。
   - 1ラウンドに取得できるアイテムは1個までとする。
   - アイテムを使っていること（誰が、どの設置面で使っているか）は、他の参加者にも見える。アイテムの結果（転がる方向や揺れ方など）は、使った本人にだけ表示し、他の参加者には見せない。
   - アイテムを置いても設置面は占有されない。設置面を占有するのは水平器だけであり、他の参加者がアイテムを使っている設置面にも水平器を置ける。
9. 試合終了後に、全員の水平器の位置と測定結果をステージ上に表示し、得点の内訳と設置直前の短い場面を見られるようにする。
10. 初期は個人戦と友人同士の対戦を中心とする。チーム戦と毎日の記録競争は発展段階で扱う。

### 4.3 記録（企画書 05章）

1. ステージごとに、自己最高記録、置いた対象、獲得した記念品を保存する。
2. 友人同士の対戦では、同じステージを再び選べるようにする。

### 4.4 アカウント（打ち合わせ決定事項）

1. 外部サービスのログイン（Apple、Google、SNSなど）は使用しない。
2. 初回起動時に、端末上でゲーム専用のアカウントを自動作成する。
3. 機種変更に備え、引き継ぎ用の手段（引き継ぎコードとパスワードなど）を提供する。方式は技術設計で決める。
4. アプリ内からアカウントを削除できるようにする（App Review Guidelines 5.1.1(v)）。

### 4.5 アプリ内課金（企画書 05章、打ち合わせ決定事項）

1. 基本プレイは無料とする。
2. 販売するのは外観のみとする（水平器、手袋、袖、携帯ケース、結果画面の演出など）。
3. 購入によって、測定精度、移動速度、設置までの時間、設置できる範囲を変えない。外観が異なっても、判定に使う寸法と測定条件は同じにする。
4. 購入の有無で対戦の組み合わせを分けない。
5. iOS では App Store のアプリ内課金、Android では Google Play Billing を使用する。
6. 購入の正当性はサーバ側で検証する（App Store Server API、Google Play Developer API）。
7. 再購入なしで購入済みの商品を復元できる手段を用意する（App Review Guidelines 3.1.1）。
8. 観光地で獲得する記念品と販売商品は、入手方法が分かる形で表示する。

### 4.6 プライバシー（打ち合わせ決定事項）

1. プライバシーポリシーを作成し、アプリ内とストアの両方から参照できるようにする。
2. App Store の App Privacy（プライバシー情報の申告）と、Google Play のデータセーフティ欄に申告する。
3. 収集する情報は、ゲームの提供に必要な範囲に限定する。外部ログインを使わないため、氏名やメールアドレスは収集しない方針とする。

## 5. 非機能要件

### 5.1 公平性と不正対策

1. 採点はサーバ側で行う。端末からは設置した面、位置、向きのみを送り、傾きと得点はサーバが保持するステージ設定から計算する。
2. 開始時刻と設置時刻は、端末の時計ではなくサーバの時刻を基準とする。通信遅延の補正方法は技術設計で決める。
3. 設置面の占有の判定（第4.2節6項）と、アイテムの取得と使用の管理はサーバ側で行う。
4. 各設置面の実際の傾きは、端末に送らずサーバだけが保持する。端末に送ると、改造したアプリで試合中に読み取れるためである。水平器の測定結果とアイテムの結果は、サーバが計算して該当する参加者にだけ送る。
5. 対戦中に送信される位置情報を使い、移動速度の上限超過や瞬間移動などの不自然な動きを検出できるようにする。
6. 購入情報はサーバ側の検証結果のみを正とする。

### 5.2 性能

1. 対象端末の範囲と、目標フレームレート（30fps、60fpsなど）は未決とする（第9章）。
2. 他の参加者の表示は、通信の揺らぎがあっても動きが不自然にならないよう補間して描画する。

## 6. 法令・規約への対応

| 対象 | 対応内容 |
|---|---|
| App Store Review Guidelines | アプリ内課金（3.1.1）、アカウント削除（5.1.1(v)）、プライバシー（5.1） |
| Google Play デベロッパー ポリシー | Google Play 請求システムの使用、データセーフティ欄、新規個人アカウントのクローズドテスト要件 |
| 個人情報保護法 | プライバシーポリシーでの利用目的の明示など |
| 特定商取引法 | 有料商品を販売するため、事業者情報などの表示を行う |
| 資金決済法 | 有償のゲーム内通貨を設けず、商品を直接購入する方式とする場合は、前払式支払手段に関する規制の対象外となる。有償通貨を設ける場合は別途対応が必要 |
| 実在観光地の再現 | 施設名称、商標、参照資料の権利、施設の撮影規約を個別に確認する（企画書 04章）。初期は一般的な部屋のみを扱う |

法令の適用関係は本書作成時点の一般的な整理であり、課金開始前に専門家の確認を受ける。

## 7. 開発段階

| 段階 | 内容 | 主な完了条件 |
|---|---|---|
| 1. 一人用の試作 | 一つの部屋で、移動、設置、2軸判定、時間記録、得点表示（企画書 06章） | iPhone 17（TestFlight）と Android エミュレータで動作する |
| 2. オンライン対戦 | 試合の進行、他の参加者のリアルタイム表示、置けない範囲の判定、アイテム、サーバ側採点 | 少人数で同じ条件の対戦ができる |
| 3. 記録とアカウント | アカウント、引き継ぎ、削除、自己最高記録、試合後の置き場所共有 | 機種変更とアカウント削除が動作する |
| 4. 課金とストア公開 | アプリ内課金、購入検証、復元、プライバシー対応、審査提出 | 両ストアで公開される |

各段階は、まず簡易的なもので作り、遊びが成立することを確認してから作り込む（2026-11-12決定）。3Dモデルは単純な形状から始め、Android 実機の調達は段階2の開始前に改めて判断する。

段階1の期間中に、課金プラグインが両OSで動作することを最小構成で確認する。Godot 向けのアプリ内課金は Godot 公式の機能ではなく、コミュニティ製のプラグインに依存するためである。

## 8. 対象外とする事項（初期版）

1. 外部サービスによるログイン
2. 能力や有利不利に影響する商品の販売
3. 実在観光地の再現ステージ（一般的な部屋で遊びを確認した後に扱う）
4. チーム戦、毎日の記録競争
